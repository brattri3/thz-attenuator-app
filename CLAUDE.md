# CLAUDE.md — THz Attenuator App

Приложение для управления и калибровки терагерцовых аттенюаторов на проволочных поляризаторах
(WGP, семейство **ATT-11-16-CA85**): считает угол поворота по нужному ослаблению и обратно, ведёт
калибровку на стенде, отмечает зашкал и границу чувствительности приёмника.

Язык документации, комментариев и коммитов — **русский**. Интерфейс приложения — английский.

## Что это за репозиторий

**Продуктовый.** Отсюда идёт поддержка и обновление приложения. Заведён 2026-08-27 переносом
продуктового контура из исследовательского `THz-Unified-Optimizer` (точка отделения и состав —
`CHANGELOG.md`). История не переносилась намеренно.

**Поток вещества односторонний:** физика зреет в исследовательском репозитории, сюда приезжает
застывший результат. Генераторы паспортов и калибровок из измерений, приёмка на измеренных данных
и просмотр измеренных кривых остались там — это станок, а не изделие. Обратного переноса не бывает.

## Гардрейлы — нарушение необратимо

- **Репозиторий публичный.** Данные конкретного экземпляра прибора сюда не попадают: ни серийный
  номер, ни снятая с него калибровка, ни измеренные спектры. `passports/*.json` закрыт
  `.gitignore` — правило не снимать. Приёмка идёт на обезличенном `SAMPLE`.
- **`git push` — только с прямого разрешения владельца.** Форс, `rm -rf`, переписывание истории —
  никогда.
- **Физику не менять молча.** Модель перенесена из исследовательского репозитория и сверена там;
  расхождение чисел приёмки означает дефект, а не улучшение. Нужна правка физики — сначала вопрос
  владельцу.
- **Правку интерфейса проверять живым запуском, а не импортом.** Оба урока получены дорого:
  мок-импорт пропускает разрыв метода, а числовые проверки не видят пропавший индикатор
  радиокнопки, запятую вместо точки в локали и срезанную рамкой подпись — эти четыре дефекта нашёл
  снимок живого окна, когда все прогоны были зелёными.
- Коммит: префикс роли `[<ID>]` + трейлеры последним абзацем без пустой строки внутри
  (`Session: <ID>`, `Reason: <в одну строку>`). Коммитить только свои пути, `git add -A` — нет.

## Команды

```
pip install -r requirements.txt
pip install PySide6-Essentials==6.11.2 pyqtgraph==0.14.0

python -m attenuator_app.cwapp                       # основное CW-приложение (PySide6)
python -m attenuator_app.tools.service_gui           # сервисное окно наладчика (tkinter)
python -m attenuator_app.tools.service_calc --help   # сервисный расчёт, два ротатора
python -m attenuator_app.tools.service_calibrate --plan   # процедуры калибровки П0…П4
```

Приёмка целиком — четыре прогона, ожидаемые числа:

```
python -m attenuator_app.cwapp.selftest           # 17/17
python -m attenuator_app.selftest                 # 13/13
python -m attenuator_app.tools.service_selftest   # модель OK, пределы OK, калибровка 8/8, приложение 7/7
python -m attenuator_app.cw_curve --selftest      # 5/5
python tools/verify_core.py                       # сверка ядра: 9 файлов
```

Дымовой прогон окна — `python -m attenuator_app.cwapp.tools.smoke_cwapp`: 70 проверок и 15
снимков, закрывает стрелки спинбокса, слайдеры углов и выбор паспорта. Он не входит в четыре
прогона выше, но правку интерфейса проверять без него нельзя — числовые прогоны интерфейс не
видят.

Опорная точка сверки интерфейса против CLI —
`service_calc --from-angle 40 --theta2 0 --freq 0.8` даёт `−4.77 дБ`, азимут `+0.023°`,
эллиптичность `+0.630°`. Расхождение здесь — дефект, а не округление.

Проверка `A7` в `service_selftest` **пропускается штатно**: она сверяет модель с независимой
реализацией из исследовательского репозитория, которого здесь нет, и говорит об этом явно.

## Физика: что не переоткрывать

- Скрещенная пара **одинаковых** WGP поляризационно нейтральна: у дна на выходе воспроизводится
  состояние источника, а не ось второй решётки. Азимут держится лучше 0.4° до ~28 дБ и полностью
  теряется в последнем градусе перед скрещением. **Это не дефект.**
- Максимум при вращении второй решётки у когерентного приёмника стоит **посередине** между осью
  первой решётки и осью анализатора, а не на совмещении. Наивный `argmax` даёт смещённый ноль.
- У мощностного приёмника вращение второй решётки даёт `cos²`, вращение первой — `cos⁴`, вдвое по
  децибелам. При калибровке важно знать, какая решётка в роторе.

Подробности и числа — `docs/attenuator_app/`.

## Координация сессий

Развёрнута 27.08 скиллом `.claude/skills/multi-agent-coordination` (upstream `2e37500`).
Две роли: **APP** (приложение) и **ORCH** (координация, релизы, поставка).

1. Назови сессию: `claude -n app` или `claude -n orch`.
2. **Прочитай `coordination/roles/<ID>.md` — единственный обязательный файл при старте.**
   Зоны — `coordination/OWNERSHIP.md`, решения владельца — `QUESTIONS.md`, задания между
   ролями — `HANDOFFS.md` (искать поиском, не читать целиком).

### Инструменты координации

```
python coordination/tools/status.py                    # сводка в CLI: роли, бэклог, worktree
python coordination/tools/worktree_launcher.py <роль>  # песочница .worktrees/<роль> на ветке role/<роль>
python coordination/tools/build_index.py               # пересобрать INDEX.md по журналам
streamlit run coordination/tools/dashboard/dashboard.py   # UI слежения за работой ролей
```

Дашборд ставится отдельно: `pip install -r coordination/tools/dashboard/requirements.txt`.
⛔ **Дашбордом не пользоваться на запись** (осмотр APP 27.08, разбор — `HANDOFFS.md`). Две
причины, обе не косметические:

- **он молча врёт по нашим журналам.** Парсер написан под английские статусы: «открыт»/«решён» и
  «блокирующий» под него не подходят, поэтому экран показывает `Open Questions: 0` и
  `Roles Active: 0 / 2` при живых открытых вопросах и двух работающих ролях. Ошибки при этом не
  выводится — оператор видит числа и верит им;
- **формы записи коммитят в один клик**, без подтверждения и превью диффа, а `append_question`
  вставляет строку после последней табличной строки во всём файле — то есть внутрь таблицы
  физических чисел по П-2 в `QUESTIONS.md`, портя её. Выключатель авто-коммита живёт в боковой
  панели, которая в Streamlit 1.62 не рендерится, и по умолчанию включён.

Читать с оговорками можно; править журналы — руками или через `status.py`. Разбор отправлен в
апстрим: [issue #6](https://github.com/DimaMuhannad/multi-agent-coordination-skill/issues/6) —
до ответа считать поведение дашборда таким, как описано выше.

⚠ Песочницы. `worktree_launcher.py` заводит рабочее дерево в `.worktrees/<роль>` на ветке
`role/<роль>`. Каждая песочница — отдельный каталог с полной копией файлов, но **общей** базой
`.git`: ветка, занятая песочницей, не удаляется, пока каталог существует, и убирать её надо
`git worktree remove`, а не удалением папки. `.worktrees/` закрыт `.gitignore`.

**Бюджет файлов ролей — мягкий.** Хук `SessionStart` предупреждает при превышении 2400 байт, но
не блокирует, и выходить за лимит можно, если это обосновано (решение владельца 27.08).
Обоснование содержательное — живой пункт, число, ловушка; не обоснование — нежелание выносить
закрытую историю в журналы.

✅ Хук идёт **чистым апстримом** (`2e37500`), локальных правок в нём нет. Три дефекта, найденные
при развёртывании, исправлены в апстриме по репорту
[issue #4](https://github.com/DimaMuhannad/multi-agent-coordination-skill/issues/4): подсчёт
размера теперь нормализует CRLF, лимит читается из `files[].limit_bytes`, а корень проекта
ищется подъёмом до `.claude`/`.git` вместо `os.getcwd()`. При обновлении скилла ничего
накатывать не нужно.

⚠ Единственное, за чем следить при обновлении: в апстриме закоммичены 22 `__pycache__/*.pyc` и
`.coverage`. Их имена длиннее лимита Windows и ломают клонирование без `core.longpaths`; сюда
они не тащатся (`.gitignore` + установка через `tar --exclude`).
