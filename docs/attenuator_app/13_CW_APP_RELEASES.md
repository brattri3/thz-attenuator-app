## 1. Схема версионирования

`MAJOR.MINOR.PATCH`, но с приборным смыслом каждого разряда:

| Разряд | Меняется, когда | Пример |
|---|---|---|
| **MAJOR** | меняется физическая конвенция или формат калибровочного файла, то есть **прежние числа перестают воспроизводиться** | смена знака затухания, смена нормировки, несовместимый формат v3 |
| **MINOR** | добавлена возможность, прежние числа не тронуты | вернули график производной, добавили экспорт |
| **PATCH** | исправление, не меняющее ни одного числа при тех же входных данных | опечатка в подписи, падение при пустом поле |

**Правило, специфичное для приборной программы:** если исправление меняет
выдаваемое число — это не PATCH. Даже если старое число было ошибочным. Такое
изменение идёт как MINOR с явной строкой в списке изменений, а если ломает
воспроизводимость прошлых протоколов — как MAJOR.

### Одной версии мало

Число, выданное программой, воспроизводимо только если известны **три**
величины. Все три показываются в окне «О программе» и попадают в каждый
экспорт, когда экспорт появится:

```
приложение     0.1.0
физическое ядро  service_calc 2026-08-24  (сверка A7 = 0.00e+00)
калибровка     SAMPLE, v2, 2026-08-18
```

Версия приложения без версии ядра и идентификатора калибровки бесполезна:
одно и то же приложение на другом калибровочном файле даст другие числа, и это
правильное поведение, а не ошибка.

### До 1.0

`0.x` означает: формат калибровочного файла и набор экранов ещё могут
меняться. **1.0.0 выпускается тогда**, когда владелец прогнал программу у
реального прибора и подтвердил приёмку — то же правило release gate, что
действует для `attenuator_app` с 2026-07-28.

## 2. Что входит в 0.1.0 (MVP)

Одно окно. Программа отвечает ровно на один вопрос: **какое пропускание даёт
пара углов на выбранной частоте.**

* источник: linear / unpolarized / partial, азимут и DOP;
* приёмник: coherent / power, ось анализатора;
* два угла `θ₁` и `θ₂` — оба поля видны всегда;
* частота;
* единицы оси: дБ или проценты;
* два графика — ортогональные сечения поверхности `T(θ₁, θ₂)`: сверху бегает
  `θ₁` при закреплённом `θ₂`, снизу наоборот; на обоих одна и та же точка,
  подписанная тремя числами;
* нормировка жёстко на отсчёт при `θ₁ = θ₂ = 0`: там 100 % и 0 дБ;
* текстовый блок: входные данные и результат, включая цену ошибки в 1° по
  каждому углу и совместную;
* строка состояния: версия, источник паспорта и кнопки «Passport…» и проверки
  обновлений;
* слайдеры к полям `θ₁` и `θ₂` — цена деления 1°, синхронно с полем в обе
  стороны; остальным полям довольно ввода с клавиатуры.

Органы управления, не влияющие на текущий расчёт, **гасятся с пояснением**
(ось анализатора при мощностном приёмнике, азимут при деполяризованном
источнике, DOP при полностью поляризованном).

Внутренние умолчания 0.1.0: офсеты насадок приняты нулевыми, диапазон обоих
углов −90…+90°, шаг сетки фиксирован.

### 2.1. Откуда берётся паспорт прибора

Порядок поиска, сверху вниз; берётся первый подошедший файл, и его имя видно в
строке состояния:

1. **явный выбор** — кнопка «Passport…» в строке состояния. Указанный файл
   обязан подойти: если он не читается как паспорт, окно говорит об этом
   красным и остаётся на прежнем паспорте. Тихо подставить вместо выбранного
   файла что-то другое нельзя — это дало бы верную арифметику по чужому прибору;
2. **рядом с программой** — сначала подкаталог `passports/`, затем сам каталог
   с исполняемым файлом, оба по маске `*.json` в алфавитном порядке.
   Посторонний JSON, случайно оказавшийся рядом, пропускается с пометкой в
   строке состояния, а не роняет запуск;
3. **зашитый образец** `SAMPLE` — последний рубеж. Строка состояния тогда прямо
   говорит `built-in SAMPLE — not your device`: считать на образце можно,
   измерять нельзя.

⚠ «Рядом с программой» в собранном `.exe` — это каталог `sys.executable`, а не
каталог `__file__`: под PyInstaller второй указывает во временный `_MEIPASS`,
который создаётся заново при каждом запуске. Ошибка здесь не проявляется из
исходников вовсе, а в поставленном `.exe` даёт подхват образца вместо паспорта
оператора. Проверка `M14` в `cwapp.selftest` поднимает поддельный `sys.frozen`
именно ради этого случая.

## 4. Отдельный репозиторий

### Зачем

Программа уходит к людям, которым не нужен исследовательский репозиторий: у
него своя история, свои зоны ролей, свои гардрейлы и 300 МБ данных. Отдельный
репозиторий даёт цепочку релизов, страницу загрузок и понятный список
изменений.

### Что переезжает

```
thz-attenuator-cw/                 (рабочее имя)
    cwapp/                         код приложения
    core/                          СНИМОК физического ядра
    calibrations/                  калибровочные файлы приборов
    docs/                          руководство оператора, соглашения
    tools/verify_core.py           сверка снимка с оригиналом
    CHANGELOG.md
    LICENSES.txt                   LGPL PySide6 и остальное
    cwapp.spec
```

### Как быть с ядром

Физика остаётся в основном репозитории — это правило рабочего пространства
(«поток вещества односторонний»). Новый репозиторий получает **снимок** ядра
плюс скрипт сверки, который сравнивает снимок с оригиналом бит-в-бит. В
проекте такой приём уже есть: `research/experiments/verify_model_core.py`.

Так исключается главный риск: расхождение физики в двух местах. Правка ядра
делается в основном репозитории, снимок обновляется одной операцией, сверка
это подтверждает.

Отвергнутые варианты: git submodule (усложняет сборку `.exe` и клонирование у
пользователя), пакет на PyPI (публиковать физику прибора отдельно незачем).

### Порядок переезда

1. Довести MVP до работающего состояния **в текущем репозитории** — так проще,
   ядро под рукой.
2. Создать репозиторий, перенести `cwapp/`, снять снимок ядра, настроить
   сверку.
3. Первый тег `v0.1.0` и первая сборка.
4. В основном репозитории оставить указатель: где теперь живёт программа.
5. `attenuator_app/cw_curve.py` **остаётся** в основном репозитории как CLI —
   он часть исследовательского слоя и уезжать не должен.

⚠ Создание репозитория и любой `git push` — только с прямого разрешения
владельца.

## 5. Проверка обновлений

Кнопка в строке состояния, **без автообновления**: приборная программа не
должна менять себя сама между двумя измерениями одной серии.

Поведение: запрос списка релизов, сравнение с текущей версией, и один из трёх
ответов — «установлена последняя», «доступна 0.2.0, посмотреть изменения»,
«проверить не удалось». Ошибка сети — обычный ответ, а не сбой: программа
обязана работать на машине без интернета, и у спектрометра это норма.

Что показывается при наличии новой версии: номер, дата, список изменений и
ссылка на загрузку. Скачивание и установку выполняет человек.

⚠ Отдельно проверить при реализации: не тянуть тяжёлых зависимостей ради
одного HTTP-запроса и не блокировать окно на время ожидания.

## 6. Выпуск релиза

1. Прогнать приёмку: самопроверка расчётного слоя, дымовой прогон окна, сверка
   с CLI.
2. Обновить `CHANGELOG.md` — по разделам «изменено / добавлено / исправлено», с
   явной пометкой всего, что меняет выдаваемые числа.
3. Поднять версию в одном месте (`cwapp/__init__.py`), остальное берёт её
   оттуда.
4. Тег `vX.Y.Z`, сборка `.exe`, публикация с контрольной суммой SHA-256.
5. Приложить `LICENSES.txt`.

Контрольная сумма обязательна: onefile-сборки регулярно вызывают ложные
срабатывания антивирусов, и у получателя должен быть способ проверить, что
файл тот самый.
