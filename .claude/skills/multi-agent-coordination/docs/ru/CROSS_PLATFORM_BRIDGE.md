# Кроссплатформенный мост: Работа любых агентов с координационным скаффолдом

Этот документ описывает, как разные инструменты (Google Antigravity, Claude Code, Cursor, Aider) могут бесшовно взаимодействовать в одном проекте, используя этот Git-ориентированный скаффолд.

## 1. Агностичность к моделям и платформам

Ключевой принцип данного подхода: **скаффолду неважно, какая нейросеть или платформа исполняет роль**. 
- Нет жестко зашитой привязки "Antigravity = Архитектор, Claude Code = Разработчик".
- Специфика определяется исключительно **содержимым командных файлов (md файлов в `coordination/roles/`)**, которые читаются при первой инициализации свежей сессии.
- Любая платформа, способная прочитать стартовый `.md` файл и сделать коммит в Git, становится полноправным участником.

## 2. Общий жизненный цикл сессии (Для любой платформы)

1. **Изоляция:** Каждая роль (независимо от того, запускается она в Antigravity, Claude Code или локально человеком) может работать в собственной ветке или `git worktree` — обычной командой `git worktree add`.
   Когда это оправдано, а когда общий каталог на `main` достаточен, см. `CHARTER.md §5`.
2. **Инициализация:** При старте агент должен получить в системный или стартовый промпт инструкцию прочитать свой файл роли: `coordination/roles/<ROLE_ID>.md`. Этот файл задает контекст, задачи и границы зоны ответственности.
   Общие для всех платформ правила лежат в **`AGENTS.md`** в корне репозитория — это кроссвендорное соглашение, с декабря 2025 переданное в Agentic AI Foundation при Linux Foundation. `CLAUDE.md` — тонкая надстройка: первой строкой `@AGENTS.md`, дальше специфика Claude Code. Инструменту, отличному от Claude Code, достаточно `AGENTS.md`; ничего claude-специфичного там быть не должно.
3. **Хуки и Бюджет:** Хук проверки бюджета (`check-context-budget.py`) срабатывает одинаково. Он носит **предупреждающий характер** (мягкий лимит). Агентам строго **запрещается** агрессивно сжимать или удалять командные файлы без явного согласия человека, управляющего проектом. Управление контекстом — привилегия человека.
4. **Коммуникация:** Общение между ролями (и между LLM разных платформ) идет асинхронно через `QUESTIONS.md` (блокирующие вопросы) и `HANDOFFS.md` (делегирование задач).
5. **Фиксация результатов:** Все коммиты должны содержать префикс и трейлер (например, `Session: frontend`), чтобы инструмент `kpi_git.py` мог корректно посчитать вклад каждой роли, независимо от того, какая платформа сгенерировала коммит.

## 3. Что именно является протоколом

Скаффолд платформенно-независим, но не «как угодно»: несколько вещей — протокол, и они одинаковы
для любого агента.

- **Трейлеры коммита** — `Session: <ID>` и `Reason: <почему>`, как предписывает `CHARTER.md §4`, а
  не `Role:`. `kpi_git.py` и CI-проверка рассчитывают именно на этот вид; одно расхождение здесь
  тихо ломает и статистику, и проверку.
- **Ключевые слова статусов и заголовки таблиц** остаются английскими даже в проекте, который
  ведётся по-русски. Текст вопросов, ответов и передач — на языке проекта. Обоснование и то, что
  происходит при нарушении, — в `references/rationale.md`.
- **`claude -n <имя>` и `claude agents --json`** — удобства Claude Code, а не требования
  скаффолда. На других платформах их просто нет; арбитром остаётся git, как и для работы с
  нескольких машин (`CHARTER.md §1`). Заводить взамен собственный реестр «кто сейчас онлайн»
  **не нужно** — см. `CONCEPT.md §3.5`.
- **Встроенные мультиагентные механизмы платформы** (субагенты и agent teams у Claude Code и
  их аналоги) — это оперативная память одной сессии: состояние лежит вне репозитория и
  удаляется вместе с сессией. Пользоваться ими можно свободно, но результат — решение,
  передача задачи, изменение состояния — пишется в журналы до конца сессии, иначе он потерян
  для всех остальных платформ и машин. Разбор — в `CONCEPT.md §6.7`.
- **Зоны владения** описаны в `OWNERSHIP.md` и с недавних пор проверяемы, а не только
  декларативны: `coordination/tools/ownership.py` рендерит из той же таблицы `.github/CODEOWNERS`
  (работает для любой платформы, потому что это GitHub, а не агент), а
  `.claude/hooks/check-path-ownership.py` блокирует запись мимо своей зоны — этот второй
  механизм специфичен для Claude Code, и на других платформах его роль выполняет CODEOWNERS
  вместе с защитой ветки.
- **Изоляция через worktree** — по умолчанию выборочная, а не поголовная: `CHARTER.md §5`
  рекомендует её для роли, которая активно правит общий код. Общий каталог на `main` — обычный
  режим работы.
