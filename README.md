# THz Attenuator App

Приложение для управления и калибровки терагерцовых аттенюаторов на проволочных поляризаторах
(WGP) — семейство **ATT-11-16-CA85**. Считает угол поворота по нужному ослаблению и обратно,
ведёт калибровку на стенде, отмечает зашкал и границу чувствительности приёмника.

Физическая основа — модель **Бланко (1986)** в формализме матриц Джонса, дополненная проводимостью
Друде и степенным членом рассеяния `ν^γ`. Состояние света переносится матрицей когерентности
`J = ⟨E E†⟩`, что позволяет одинаково описывать когерентный и мощностной приёмник и не терять
фазу утечки параллельного канала.

## Что внутри

| Что | Запуск | Для кого |
|---|---|---|
| **CW-приложение** (основное, PySide6) | `python -m attenuator_app.cwapp` | оператор у прибора |
| Сервисный расчёт, два ротатора (CLI) | `python -m attenuator_app.tools.service_calc --help` | наладчик |
| Сервисное окно (tkinter) | `python -m attenuator_app.tools.service_gui` | наладчик |
| Процедуры калибровки П0…П4 | `python -m attenuator_app.tools.service_calibrate --plan` | оператор на стенде |
| Приложение v0.3 (tkinter, legacy) | `python -m attenuator_app.gui_entry` | до конца приёмки у прибора |

## Установка

```
pip install -r requirements.txt
pip install PySide6-Essentials==6.11.2 pyqtgraph==0.14.0
```

Qt ставится отдельной командой намеренно: полный пакет `PySide6` тянет QtWebEngine, Qt3D и Charts —
сотни мегабайт, из которых приложению не нужно ничего. Сервисные окна работают на `tkinter` из
стандартной поставки Python и Qt не требуют вовсе.

## Паспорт прибора — обязательно прочитать

Параметры конкретного экземпляра живут **в отдельном файле-паспорте**, который поставляется вместе
с изделием. В репозитории его нет и не будет: публичный репозиторий — не место для данных
отдельного прибора.

* **Ваш паспорт** кладётся в каталог `passports/` рядом с программой (см. `passports/README.md`).
  `.gitignore` закрывает этот путь, чтобы паспорт не уехал в открытый доступ случайным `git add`.
* **Обезличенный образец**, на котором идут приёмочные прогоны, —
  `attenuator_app/passports/SAMPLE.json` и `attenuator_app/tools/calibration/SAMPLE.json`.
  Числа в них физически осмысленны, но **для измерений они не годятся**.

## Приёмка

```
python -m attenuator_app.cwapp.selftest
python -m attenuator_app.selftest
python -m attenuator_app.tools.service_selftest
python -m attenuator_app.cw_curve --selftest
```

Ожидается: `cwapp` 12/12 · база 13/13 · сервисное приложение (модель, пределы, калибровка 8/8,
приложение 7/7) · CW-кривая 5/5. Опорная точка сверки интерфейса против CLI:
`service_calc --from-angle 40 --theta2 0 --freq 0.8` даёт `−4.77 дБ`, азимут `+0.023°`,
эллиптичность `+0.630°`.

Одна проверка в этом репозитории **пропускается штатно**: `A7` сверяет модель с независимой
реализацией из исследовательского репозитория, которого здесь нет, и сообщает об этом явно.
Замена на замороженный эталон в `tests/golden/` — открытая задача.

## Физика: что не переоткрывать

* Скрещенная пара **одинаковых** WGP поляризационно нейтральна: у дна на выходе воспроизводится
  состояние источника, а не ось второй решётки. Азимут держится лучше 0.4° до ~28 дБ и полностью
  теряется в последнем градусе перед скрещением. Это не дефект прибора и не ошибка расчёта.
* Максимум при вращении второй решётки у когерентного приёмника стоит **посередине** между осью
  первой решётки и осью анализатора, а не на совмещении. Наивный `argmax` даёт смещённый ноль
  калибровки.
* У мощностного приёмника вращение второй решётки даёт `cos²`, вращение первой — `cos⁴`, то есть
  вдвое по децибелам. При калибровке важно знать, какая решётка в роторе.

Подробности и числа — `docs/attenuator_app/`.

## Происхождение

Приложение выросло внутри исследовательского репозитория `THz-Unified-Optimizer`, где живут
данные измерений, подгонка модели и научная часть. Сюда перенесён только продуктовый контур;
поток односторонний — физика зреет в исследовательском репозитории, сюда приезжает застывший
результат. Генераторы паспортов и калибровок из измерений остались там же: это станок, а не
изделие.
