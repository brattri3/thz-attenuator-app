# AGENTS.md — THz Attenuator App

Приложение для управления и калибровки терагерцовых аттенюаторов на проволочных поляризаторах
(WGP, семейство **ATT-11-16-CA85**): считает угол поворота по нужному ослаблению и обратно, ведёт
калибровку на стенде, отмечает зашкал и границу чувствительности приёмника.

Документация, комментарии и коммиты — **русский**. Интерфейс приложения — английский.

## Что это за репозиторий

**Продуктовый.** Отсюда идёт поддержка и обновление приложения. Заведён 2026-08-27 переносом
продуктового контура из исследовательского `THz-Unified-Optimizer` (точка отделения и состав —
`CHANGELOG.md`). История не переносилась намеренно.

**Поток вещества односторонний:** физика зреет в исследовательском репозитории, сюда приезжает
застывший результат. Генераторы паспортов и калибровок из измерений, приёмка на измеренных данных
и просмотр измеренных кривых остались там — это станок, а не изделие. Обратного переноса не бывает.

## Твой старт

Две роли-сессии делят этот репозиторий: **APP** (приложение) и **ORCH** (координация, релизы,
поставка).

1. **Назови себя.** Твоя сессия должна знать свою роль раньше, чем что-то запишет. Как именно
   назвать себя — зависит от инструмента (для Claude Code — `CLAUDE.md`); неопционально то, что
   ответ есть и совпадает со строкой в `coordination/BOARD.md`.
2. **Прочитай `coordination/roles/<ID>.md` — единственный обязательный файл при старте.** Там
   зона, что открыто, что дальше и куда идти за подробностями.

Дальше ничего не обязательно читать сразу — остальное по необходимости: зоны —
`coordination/OWNERSHIP.md`, решения владельца — `QUESTIONS.md` (искать поиском, не читать
целиком после того, как вырос), задания между ролями — `HANDOFFS.md` (тоже поиском).

> **Кто сейчас работает** — вопрос к git, не к этому файлу: свежие коммиты, активные ветки,
> `.worktrees/`. `git fetch origin <ветка>` — прежде чем делать любое утверждение про `origin`:
> ссылка на удалённую ветку — это кеш и может отставать от уже случившегося пуша, в том числе из
> другой песочницы на этой же машине (`coordination/CHARTER.md §4`).

## Гардрейлы — нарушение необратимо

- **Репозиторий публичный.** Данные конкретного экземпляра прибора сюда не попадают: ни серийный
  номер, ни снятая с него калибровка, ни измеренные спектры. `passports/*.json` закрыт
  `.gitignore` — правило не снимать. Приёмка идёт на обезличенном `SAMPLE`.
- **`git push` — только с прямого разрешения владельца.** Форс, `rm -rf`, переписывание истории —
  никогда.
- **Физику не менять молча.** Модель перенесена из исследовательского репозитория и сверена там;
  расхождение чисел приёмки означает дефект, а не улучшение. Нужна правка физики — сначала вопрос
  владельцу.
- **Правку интерфейса проверять живым запуском, а не импортом.** Оба урока получены дорого:
  мок-импорт пропускает разрыв метода, а числовые проверки не видят пропавший индикатор
  радиокнопки, запятую вместо точки в локали и срезанную рамкой подпись — эти четыре дефекта нашёл
  снимок живого окна, когда все прогоны были зелёными.
- **Работай только в своей зоне.** Запрос вне зоны — не твоя работа: объясни, чья это зона, заведи
  в `coordination/HANDOFFS.md`, предложи переключить владельца в нужную сессию. Не уверен, чья
  зона — спроси. `coordination/OWNERSHIP.md` — карта.
- Коммит: префикс роли `[<ID>]` + трейлеры последним абзацем, пустая строка перед блоком, без
  пустой строки внутри (`Session: <ID>`, `Reason: <в одну строку>`). Коммитить только свои пути,
  `git add -A` — нет.

## Команды

```
pip install -r requirements.txt
pip install PySide6-Essentials==6.11.2 pyqtgraph==0.14.0

python -m attenuator_app.cwapp                       # основное CW-приложение (PySide6)
python -m attenuator_app.tools.service_gui           # сервисное окно наладчика (tkinter)
python -m attenuator_app.tools.service_calc --help   # сервисный расчёт, два ротатора
python -m attenuator_app.tools.service_calibrate --plan   # процедуры калибровки П0…П4
```

Приёмка целиком — четыре прогона, ожидаемые числа:

```
python -m attenuator_app.cwapp.selftest           # 30/30
python -m attenuator_app.selftest                 # 13/13
python -m attenuator_app.tools.service_selftest   # модель OK, пределы OK, калибровка 8/8, приложение 7/7
python -m attenuator_app.cw_curve --selftest      # 5/5
python tools/verify_core.py                       # сверка ядра: 9 файлов
```

Дымовой прогон окна — `python -m attenuator_app.cwapp.tools.smoke_cwapp`: 15 снимков, закрывает
стрелки спинбокса, слайдеры углов, выбор паспорта и диалоги обновлений. Он не входит в четыре
прогона выше, но правку интерфейса проверять без него нельзя — числовые прогоны интерфейс не
видят.

⚠ По умолчанию прогон идёт на платформе `offscreen`, и четыре пиксельные проверки стрелок там
**пропускаются с указанием причины**: нативный стиль под offscreen стрелки не рисует. Чтобы
выполнить и их, запускать `QT_QPA_PLATFORM=windows`; в этом режиме прогон зелёный целиком.

Опорная точка сверки интерфейса против CLI —
`service_calc --from-angle 40 --theta2 0 --freq 0.8` даёт `−4.77 дБ`, азимут `+0.023°`,
эллиптичность `+0.630°`. Расхождение здесь — дефект, а не округление.

Проверка `A7` в `service_selftest` **пропускается штатно**: она сверяет модель с независимой
реализацией из исследовательского репозитория, которого здесь нет, и говорит об этом явно.

## Физика: что не переоткрывать

- Скрещенная пара **одинаковых** WGP поляризационно нейтральна: у дна на выходе воспроизводится
  состояние источника, а не ось второй решётки. Азимут держится лучше 0.4° до ~28 дБ и полностью
  теряется в последнем градусе перед скрещением. **Это не дефект.**
- Максимум при вращении второй решётки у когерентного приёмника стоит **посередине** между осью
  первой решётки и осью анализатора, а не на совмещении. Наивный `argmax` даёт смещённый ноль.
- У мощностного приёмника вращение второй решётки даёт `cos²`, вращение первой — `cos⁴`, вдвое по
  децибелам. При калибровке важно знать, какая решётка в роторе.

Подробности и числа — `docs/attenuator_app/`.

## Инструменты координации

```
python coordination/tools/build_index.py               # пересобрать INDEX.md по журналам
python coordination/tools/discover.py                  # разведка перед изменением оснастки
python coordination/tools/upgrade.py --from <путь>      # сверка установленного с новой версией скилла
git worktree add .worktrees/<роль> -b role/<роль>       # песочница на общей базе .git
streamlit run coordination/tools/dashboard/dashboard.py   # UI слежения за работой ролей, read-only
```

Дашборд ставится отдельно: `pip install -r coordination/tools/dashboard/requirements.txt`. Он
read-only по конструкции, путь записи апстрим убрал полностью (обновление скилла 2026-09-17,
подробности и разбор находок — `coordination/ACTIVITY.md`).

**Словарь статусов — только английские протокольные токены**, независимо от языка документации:
`QUESTIONS.md` → `Status: open|resolved|closed`, `Type: blocking|non-blocking`; `HANDOFFS.md` →
`- **Status:** open|taken|done`; `BOARD.md` → `active|idle|stale|blocked`. Текст вопроса, ответа,
резюме остаётся русским — токен статуса нет. Инструменты не гадают перевод: слово вне словаря
репортится как нераспознанное и не считается ни открытым, ни закрытым.

⚠ Песочницы. `git worktree add` заводит рабочее дерево на ветке `role/<роль>`. Каждая песочница —
отдельный каталог с полной копией файлов, но **общей** базой `.git`: ветка, занятая песочницей, не
удаляется, пока каталог существует, и убирать её надо `git worktree remove`, а не удалением папки.
`.worktrees/` закрыт `.gitignore`.

**Отложено сознательно** (не перенесено при обновлении скилла 2026-09-17, решение владельца
впереди — `QUESTIONS.md` П-6): хуки владения путями и трейлеров коммита, `.github/CODEOWNERS` +
CI-проверка, реструктуризация `BOARD.md` под апстримную схему колонок.

   `.exe` — иначе получатель не может заменить Qt, чего требует LGPL. Наружу уходит zip-архив,

## Что журналы, а что рабочая память

`BOARD.md`, `QUESTIONS.md`, `HANDOFFS.md` и `ACTIVITY.md` — durable-память проекта: живут в git,
переживают каждую сессию, читаемы любым инструментом. Подагенты/teammates внутри одной сессии —
рабочая память: решение или смена состояния, которые должны пережить сессию, записываются сюда,
иначе теряются.
